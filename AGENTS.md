# TierTask AI Agent Rules

> [!IMPORTANT]
> Update this file, [`ARCHITECTURE.md`](ARCHITECTURE.md), [`spec/TDF_SPEC_0.8.0.md`](spec/TDF_SPEC_0.8.0.md), and [`spec/UI_DESIGN_SYSTEM.md`](spec/UI_DESIGN_SYSTEM.md) when the architecture, directory structure, file names, TierTask Data Format (`TDF`) schema, or UI design guidelines change. Keep this file well below the `24,000`-byte per-file rule limit so no rules truncate.

## 1. Core Principles, Scope & Workflow
- **Test-Driven Development (`P-TDD-FIRST`):** Develop every feature, domain rule, parser routine, notifier, repository method, widget, and bug fix with strict Red-Green-Refactor TDD:
  1. **Red:** Write failing unit (`test/`) or widget (`testWidgets`) tests FIRST and verify failure via `flutter test`.
  2. **Green:** Write minimal production code in `lib/` to make the tests pass.
  3. **Refactor:** Clean up and optimize while keeping `flutter test` and `flutter analyze --fatal-infos --fatal-warnings` green.
- **Language & Tone (`P-LANG-RULES`):** Write all AI responses, code, identifiers, comments, docs, tests, error messages, and commits in concise, factual English (ASD-STE100 80%). Never use emojis, filler text, marketing adjectives, greetings, or Markdown horizontal rules (`---`) outside YAML frontmatter. Avoid em dashes (`—`); use them only in rare, clearly justified exceptions (prefer colons, commas, parentheses, or separate sentences).
- **Scope & Supported Targets:** Manage tasks across six dynamically derived tiers (`Focus`, `Ready`, `Planned`, `Blocked`, `Someday`, `Completed`) on **Linux, Android, and Windows** (`linux/`, `android/`, `windows/`) with **English (`en`, default) and German (`de`)** ARB localization (`lib/l10n/app_en.arb`, `lib/l10n/app_de.arb`, compiled via `flutter gen-l10n`), using a deterministic pull-system and a single `.tdf` file ([`spec/TDF_SPEC_0.8.0.md`](spec/TDF_SPEC_0.8.0.md)) stored locally or synced via any standards-compliant WebDAV server. iOS, macOS, Web, and other backends are unsupported.
- **Standard Library First (`P-STDLIB-FIRST`):** Prefer the Dart SDK (`dart:async`, `dart:collection`, `dart:convert`, `dart:core`, `dart:ffi`, `dart:io`) and official Flutter packages (`package:flutter`, `package:flutter_localizations`) over third-party dependencies. Keep `pubspec.yaml` minimal and implement TDF scanning/parsing/serialization (`lib/services/tdf_*.dart`), SHA-256 (`lib/services/sha256_service.dart`), local file I/O and host-local cooperative locking (`dart:io` `File`, `dart:ffi` in `lib/repositories/`), and WebDAV HTTP (`dart:io` `HttpClient`) directly with the Dart SDK.
- **Strict Type & Null Safety (`P-STRICT-TYPES`, `P-NULL-SAFE`):** Target Dart 3+ and Flutter (Material 3) with sound null safety and `strict-casts`, `strict-inference`, and `strict-raw-types`. Forbid `dynamic`, unchecked `as`, mutable global state, null-assertion (`!`), uninitialized `late` without guaranteed lifecycle initialization, and unchecked `.cast<T>()` (allowed only for proven mathematical invariants). Deconstruct nullables with pattern matching (`if (value case final v?)`), `??`, or `?.`.
- **Version Control:** NEVER commit changes unless explicitly instructed by the user.
- **Clarity & Responsibility-Based Modularity (`P-VERTICAL-CLARITY`, `P-FILE-SIZE`):** Prefer flat control flow, small helpers, stateless subsystem classes (`const Class._()`), and composable private `StatelessWidget` classes over deep nesting or dense expressions. Split `lib/` files by domain/widget responsibility; NEVER refactor, compress, or split existing `lib/` or `test/` files solely to reduce line count. Forbid `part`, `part of`, and barrel `export` shims in hand-written `lib/`, `test/`, and `packages/tiertask_ui/lib/src/` (sole scoped package barrel exception: `packages/tiertask_ui/lib/tiertask_ui.dart`; consumers in `test/` and `example/` MUST import `package:tiertask_ui/tiertask_ui.dart` and never `package:tiertask_ui/src/...`). Use `tiertask_dev.py outline` and targeted `read_file` line ranges instead of reading whole files.
- **Token Efficiency:** Avoid redundancy across code, docs, rules, and skills. Preserve all business logic, public signatures, error types, and test semantics during refactors.
- **Zero Dead Code (`P-NO-DEAD-CODE`):** Write only directly called functions, methods, classes, fields, enum variants, providers, and imports; delete orphans in the same edit. Forbid speculative helpers, unused members, hypothetical fallbacks, and commented-out code. *Stub exception:* minimal active no-op stubs wired into the call graph for unimplemented downstream stages are permitted.

## 2. Deterministic `.dart` File Layout
Place core logic in `snake_case.dart` leaf files named after their primary class or domain, in this exact 7-part vertical order:
1. **License Header (`P-LICENSE-HEADER`):** Verbatim GPL-3.0 block at line 1 followed by one blank line:
   ```dart
   // TierTask
   // Copyright (C) 2026  Stefan Stark
   //
   // This program is free software: you can redistribute it and/or modify it under
   // the terms of the GNU General Public License as published by the Free Software
   // Foundation, either version 3 of the License, or (at your option)
   // any later version.
   //
   // This program is distributed in the hope that it will be useful, but WITHOUT
   // ANY WARRANTY; without even the implied warranty of MERCHANTABILITY or FITNESS
   // FOR A PARTICULAR PURPOSE.  See the GNU General Public License for more details.
   //
   // You should have received a copy of the GNU General Public License along with
   // this program.  If not, see <https://www.gnu.org/licenses/>.
   ```
2. **Library Doc:** Optional `///` file doc (`///` for documentation; `//` only for non-obvious domain quirks; never `/* ... */`).
3. **Imports (`P-DIRECTIVES-ORDER`):** Three ASCII-alphabetized groups separated by one blank line (`directives_ordering`): `dart:`, `package:`, then relative imports in `lib/` (`prefer_relative_imports`) or `package:tiertask/...` in `test/`. Never import another package's `src/`; use `show`/`hide`/`as` only to resolve collisions.
4. **Constants & Providers:** Alphabetized file-local `const` items and top-level Riverpod `Provider` / `NotifierProvider` declarations (`public` before `_private`).
5. **Types & Member Order (`P-CLASS-COHESION`):** `enum`, `sealed class`, `class`, `extension`, `typedef` (`public` before `_private`), each owning one cohesive responsibility (extract `const Class._()` into a leaf file only for a distinct subsystem). Strict member order inside every type:
   - Constructors (primary `const`/unnamed -> named -> `factory`)
   - `static const` and `static final` fields (alphabetized)
   - `final` instance fields (`public` before `_private`, alphabetized or constructor order)
   - Getters and setters (alphabetized)
   - Lifecycle overrides (`initState`, `didUpdateWidget`, `dispose`, `build`)
   - Public methods (alphabetized), then `_private` methods (alphabetized)
   - `Object` overrides (`operator ==`, `hashCode`, `toString`)
6. **Top-Level Functions:** Alphabetized pure helpers (`public` before `_private`).
7. **Tests (`P-TEST-MIRROR`):** Mirror `lib/` under `test/` (`models/`, `services/`, `repositories/`, `providers/`, `presentation/`, `ui/`) or map extracted subsystem leaves (`1–3` suites) in `.agents/scripts/tiertask_dev.py`; no line-count caps on test files.

## 3. Architecture, Types & Idioms
- **Formatting & Naming (`P-NO-ABBREV-VARS`):** 2-space `dart format`, no trailing whitespace, trailing commas (`require_trailing_commas`), Effective Dart casing (`UpperCamelCase`, `lowerCamelCase`, `snake_case`). Never abbreviate variable names (`configuration`, `repository`, `element`, `task`, `response`; loop indices `i`, `j` allowed).
- **Mandatory Docs (`P-FN-DOCS`):** Document every production type, constructor, method, getter, top-level function, and provider (`public` and `_private`) with concise `///` English comments (`P-LANG-RULES`). Omit `///` on `test()` and `testWidgets()` blocks unless explaining a non-obvious edge case or attack vector.
- **Immutability & Constructors (`P-IMMUTABLE-MODELS`, `P-CONST-WIDGETS`):** Favor `@immutable` domain models (`final` fields, `List.unmodifiable`/`Map.unmodifiable`, `copyWith`, value `==`/`hashCode`), `const` constructors/literals, `super.key` (`use_super_parameters`), named classes or named Dart 3 records over positional tuples, and 2-state enums or `sealed class` over ambiguous booleans.
- **Errors, Global Boundaries & State (`P-GLOBAL-ERROR-BOUNDARY`, `P-ERR-PRESERVE`, `P-ATOMIC-STATE`):**
  - Register `FlutterError.onError` and `PlatformDispatcher.instance.onError` in `main.dart` so uncaught errors never terminate the event loop or leak stack traces in UI.
  - Use typed domain exceptions or `sealed class` results (`WebDavException`, `LocalFileException`). Never throw raw strings, return untyped error maps, swallow exceptions (`catch (_) {}`), or display unsanitized system exception text. Preserve causes and stack traces (`Error.throwWithStackTrace`, `rethrow`, typed `cause`).
  - Await all `Future`s (`unawaited_futures`), guard async transitions (`AsyncValue.guard`), serialize concurrent mutations, and preserve or roll back immutable `TaskBoard` state on persistence failure.
- **Unidirectional Architecture, DAG, I/O & Security (`P-UDF-ARCHITECTURE`, `P-ACYCLIC-DAG`, `P-IO-ISOLATION`, `P-WEBDAV-API`, `P-SECRET-HYGIENE`, `P-TRANSPORT-SECURITY`):**
  - Data flows unidirectionally: `lib/ui/` -> `lib/presentation/` -> `lib/providers/` -> `lib/models/`, `lib/services/`, `lib/repositories/`. `lib/ui/` must NEVER import `lib/repositories/*` or `lib/services/*` directly and must NEVER reference repository, service, or native-picker providers (enforced by `tiertask_dev.py`).
  - Maintain **`0` circular import SCCs** across `lib/` and strict bottom-up layer rank order: `0: lib/services/app_logger.dart` (`AppLogSink`) `< 1: lib/models/* < 2: lib/l10n/* < 3: lib/services/* < 4: lib/repositories/* < 5: lib/providers/* < 6: lib/presentation/* < 7: lib/ui/* < 8: lib/main.dart`. Forbid upward imports.
  - Isolate all network (`HttpClient`), filesystem (`File`), native locking (`dart:ffi`), and secure storage (`flutter_secure_storage`) I/O inside `lib/repositories/`; zero `dart:io` or `dart:ffi` imports anywhere in `lib/` outside `lib/repositories/`. Centralize WebDAV HTTP in `lib/repositories/webdav_repository.dart` and local `.tdf`, locking, and log I/O in `local_file_repository.dart`, `local_file_operations.dart`, and `host_file_lock.dart`.
  - Never hardcode secrets or log via `print()`/`debugPrint()` (`avoid_print`); redact passwords and auth headers from `toString()` and exceptions.
  - Enforce strict TLS validation (never bypass via `badCertificateCallback`), reject non-HTTP(S) schemes and URL userinfo, keep Android `usesCleartextTraffic="false"` and `allowBackup="false"`, avoid `runtimeType.toString()` branching, and build releases with `--obfuscate --split-debug-info=<dir>`.
- **Exhaustiveness & Rebuild Scoping (`P-EXHAUSTIVE-SWITCH`, `P-MASK-SAFE`, `P-SELECT-REBUILDS`):** Use exhaustive Dart 3 `switch` over `enum`/`sealed class` without redundant `default:`. Replace chained booleans (`isLoading`, `isError`, `isSuccess`) with one `enum`/`sealed class`. Scope `ref.watch` via `.select(...)` and localize `StatefulWidget` state to leaf widgets.
- **Flat Flow & Widget Modularity (`P-FLAT-CONTROL-FLOW`, `P-FLATTEN-BUILD`):** Keep business logic indentation $\le 3$ levels using pattern matching and early guards (`return`/`continue`/`break`). Keep `build()` and action dispatchers $< 40$ lines; extract UI subtrees into private `StatelessWidget`/`ConsumerWidget` classes rather than helper methods returning `Widget`.
- **UI Design System (`P-UI-DESIGN-SYSTEM`):** All work on `packages/tiertask_ui/`, `lib/ui_v2/`, redesigned `lib/ui/`, themes, or UI proposals (`TEP-015` Phases 2–4) MUST activate the **`ui-design-system`** skill and enforce [`spec/UI_DESIGN_SYSTEM.md`](spec/UI_DESIGN_SYSTEM.md) (flat `1px` borders, surface alternation, WCAG AA `>= 4.5:1` `Calm`/`Plum Umber` tokens, 17-widget reuse cap, breakpoints `<=720 / 721..820 / >820`, docked composer/actions decoupled from floating notices, inline active-label filter, unified single-expand entity cards, non-jumping task creation, `1px` focus rings, keyboard/a11y parity).
- **Analyzer & Resource Disposal (`P-NO-IGNORE`, `P-DISPOSE-RESOURCES`):** Never use `// ignore:` or `// ignore_for_file:`. Dispose every `TextEditingController`, `FocusNode`, `ScrollController`, `AnimationController`, `StreamSubscription`, and `HttpClient`; check `if (!mounted) return;` before using `BuildContext` or `setState` across `await`.

## 4. Memory, Parsing & Performance
- **Zero-Waste Allocations (`P-ZERO-ALLOC`):** Accept `Iterable<T>` or unmodifiable views for read-only parameters. Avoid redundant `.toList()`, `.toSet()`, `List.from()`, or `.toString()` inside loops or `build()`. Compile `RegExp` once as `static final`.
- **Bounded Inputs (`P-BOUND-ALLOC`):** Enforce every `spec/TDF_SPEC_0.8.0.md` Section 6.2 `maxTdf*` bound (`lib/models/tdf_error.dart`) and `connectionTimeout` BEFORE reading, scanning, or allocating the $(N+1)$-th element. Use `StringBuffer` for multi-line serialization.
- **Single-Pass Scanning & Zero-Copy (`P-ZERO-COPY`, `P-NO-QUADRATIC`):** Scan, parse, and serialize `.tdf` in a single $O(N)$ pass without `RegExp` or $O(N^2)$ patterns (`List.removeAt(0)` in loops, repeated board scans, chained `.replaceAll()`) per `spec/TDF_SPEC_0.8.0.md` and **`tdf-spec-workflow`**. Prefer `startsWith()`, `indexOf()`, code-unit checks, and substring views over `.split()`.
- **Pragmatic Boundary:** Never sacrifice `P-VERTICAL-CLARITY` or `P-IMMUTABLE-MODELS` (`copyWith`, `List.unmodifiable` on bounded collections) for micro-optimizations.
- **Flat Loops & Combinators (`P-NO-NESTED-LOOPS`, `P-LOOP-MODULARITY`, `P-FUNCTIONAL-COMBINATORS`):** Never nest loops or place multi-arm `switch`/deep `if/else` inside loops (extract a stateless helper). Keep loop bodies single-level and $< 25$ lines; order `switch` arms by declaration order. Prefer flat `for` + helper over deep `.where()`/`.map()` chains or closures with control flow.
- **Lazy Lists (`P-LAZY-LISTS`):** Use `ListView.builder` or `SliverList.builder` with deterministic `ValueKey`s for dynamic lists.

## 5. Testing, Workflows & Verification
- **Test Harness & Assertions (`P-TEST-MIRROR`):** Mount isolated leaf widgets via `pumpLeafWidget` (`FakeTaskNotifier`) in `test/ui/test_helpers.dart`. Reset `HttpOverrides.global = null;` in `setUp()` for loopback `HttpServer` tests. Prefer semantic matchers (`contains`, `equals`, `isA<T>`, `throwsA`) and add `reason:` strings in loops, table-driven cases, and multi-step assertions.
- **Mandatory Edge-Case Categories:**
  - `M-EXHAUSTIVE-STATE-TESTS`: Every `enum` variant, `sealed class` branch, and `TdfErrorKind` in `spec/TDF_SPEC_0.8.0.md` Appendix A.1.
  - `M-EXTREME-BOUND-TESTS`: WIP limits ($N-1$, $N$, $N+1$), 30-day UTC pruning ($29$, $30$, $31$ days), all `spec/TDF_SPEC_0.8.0.md` Section 6.2 `maxTdf*` bounds, and empty/whitespace inputs.
  - `M-DELIM-INJECT-TESTS`: Brace, quote, escape, inline `#` comment, CRLF/LF, control character, and malformed header/directive injection.
  - `M-URI-PATH-EDGE-TESTS`: WebDAV URL and local/remote path edge cases (`..`, null bytes, leading/trailing slashes, POSIX/Windows separators, query/fragment injection, special chars, missing scheme, empty host).
  - `M-IO-TESTS`: Isolated WebDAV (`GET`/`PUT` status, timeouts, TLS/socket errors, auth), local `.tdf` I/O (missing init, permission/FS errors, `maxTdfFileBytes`), and secure storage via mocks, `Directory.systemTemp`, or loopback `HttpServer` (no external network).
  - `M-REAL-MECHANICS-TESTS`: Exercise real end-to-end mechanics without synthetic shortcuts: (1) full `Conflict/Error -> Self-Write/Resume -> New External Input` cycles with real `Directory.watch`/repository side effects; (2) queued mutations (`candidateOriginBoard`) across external additions, tombstoned `task`/`label`/`location` deletions, `deleted.generation` advances (untouched and edited retired entities), and same-timestamp payload/`queue` tie-breaks; (3) structural invalidation (`queue` membership/order) alongside entity edits for undo/cache pruning; (4) mid-flight UI frames while async saves suspend (`Completer` before `pumpAndSettle`) plus workspace/mode/path switches across `await` boundaries (`AsyncLoading`, `_inFlightSync`). Permanently codify every discovered bug class as a regression test.
- **Parallel Subagent Isolation (`P-SUBAGENT-ISOLATION`):** Partition concurrent write subagents into strictly disjoint file `Write Set`s. Subagents run only `flutter analyze --no-pub` and `flutter test --no-pub --no-test-assets <assigned_tests>`; run `tiertask_dev.py arch --sync-tree` and `verify --full --fix` once at the wave barrier.
- **Skills & Proposals:**
  - **`tep` (`.agents/skills/tep/SKILL.md`):** Create a TEP in `.agents/proposals/` ONLY on explicit `/tep` or user confirmation; never for minor UI tweaks or bug fixes. Proactively recommend a TEP for high-complexity/cross-layer changes or any `spec/TDF_SPEC_0.8.0.md` change (during `/plan`, still write the full plan and add a `> [!IMPORTANT]` TEP recommendation).
  - **`spec-verification-loop` (`/verify-spec <path>`, `/tep <path>`):** Run for auditing or finalizing specs (`spec/TDF_SPEC_0.8.0.md`, `spec/UI_DESIGN_SYSTEM.md`, `ARCHITECTURE.md`, `README.md`) and TEPs.
  - **`tiertask-dev-workflow`, `tdf-spec-workflow`, `ui-design-system`, `update-documentation`, `changelog-updater`:** Follow for TDD cycles, TDF changes, UI design-system compliance (`spec/UI_DESIGN_SYSTEM.md`), doc sync, and user-facing `CHANGELOG.md` updates (never modify `CHANGELOG.md` when fixing unreleased code).
- **CLI Automation (`python3 .agents/scripts/tiertask_dev.py`):** Use `outline`, `find <q1> [...] [--layer <...|ui_pkg>]`, `deps`, `l10n`, `arch`, `scaffold`, `log [path] [--level] [--tag] [--event] [--summary]`, and `verify --fast --fix` / `--full --fix` (format, static `AGENTS.md`/`P-ACYCLIC-DAG`/`P-UI-ISOLATION`/`l10n`/`arch` checks, `flutter analyze`, and `flutter test` across root, `packages/tiertask_ui/`, and `packages/tiertask_ui/example/`).

## 6. Diagnostic Logging & Instrumentation Policy
1. **Mandatory Structured Logging:** When adding, modifying, or debugging domain mutations (`TaskBoard`, `TaskBoardEvaluator`, `TaskNotifier`), TDF parsing/serialization (`TdfService`, `TdfBlockParser`, `TdfSerializer`), merge/sync logic (`TaskBoardSync`, `TaskBoardReconciler`), storage/external backends (`LocalFileRepository`, `HostFileLockManager`, `WebDavRepository`, `LocationRepository`, `LinkLauncherRepository`), or lifecycle/settings flows, add or update `AppLogger.event(...)` (`lib/services/app_logger.dart`) using `<UTC-ISO> [<LEVEL>] [<TAG>] <event> | <key=value ...>` with `LogLevel` (`debug`, `info`, `warn`, `error`, `crash`) and `LogTag` (`lifecycle`, `tdf`, `domain`, `sync`, `storage`, `ui`).
2. **Debugging Expansion & Deduplication:** During bug investigations or test failures, instrument decision branches, edge cases, and catch blocks so runtime behavior is traceable in `LogViewerDialog` (`lib/ui/widgets/log_viewer_dialog.dart`) and `tiertask_dev.py log`. Gate pure model evaluations (`eval.summary`, `eval.blocked`) behind `AppLogger.shouldLog(LogLevel.debug)` and deduplicate against UI rebuild spam.
3. **Privacy, Retention & No-Op Invariant:** Never log credentials, raw `Authorization` headers, raw GPS coordinates (`latitude`/`longitude`), street addresses, Wi-Fi BSSIDs, raw task/label/scheduling notes, link titles/URIs, or task `history` text (`AppLogger.sanitize`, `AppLogger.registerSecret`). Gate all logging behind `WebDavConfig.diagnosticsEnabled` (`AppLogger.shouldLog`) with zero allocations when disabled; retain dated logs (`tiertask_<YYYY-MM-DD>_<platform>_<workspaceId>.log`, `maxRetainedLogDays = 7`, `maxRetainedLogFiles = 5`) across clean exits and delete local/WebDAV logs immediately when disabled or cleared.
