# TierTask Development Workflow

## 0. Fast-Path Discovery & Automation (`tiertask_dev.py`)
1. **Zero-Pagination Symbol & Spec Lookup:** Before reading large files (`> 400` lines) or `spec/TDF_SPEC_0.6.0.md`, run `python3 .agents/scripts/tiertask_dev.py outline <files...>` (which reports exact `StartLine-EndLine` ranges, class line spans, and `_private` method counts) or `python3 .agents/scripts/tiertask_dev.py find <query1> [<query2> ...]` (multi-query search) to obtain exact line ranges and method/constructor signatures, then call `read_file` with targeted `StartLine` and `EndLine`. Never paginate through whole files in 800-line blocks.
2. **Impact & Reverse Dependency Check:** Before modifying shared UI screens, widgets, models, or providers, run `python3 .agents/scripts/tiertask_dev.py deps <lib_path>` to identify direct imports, reverse dependents, and mapped mirror/subsystem test suites.
3. **Single-Command Localization (`l10n`):** Add, update, or remove ARB localization strings in one step via `python3 .agents/scripts/tiertask_dev.py l10n --set <key> "<en>" "<de>" [--desc "<desc>"]` (which auto-generates `@<key>` metadata and `{placeholder}` definitions and runs `flutter gen-l10n`). Avoid reading and editing `app_en.arb` and `app_de.arb` manually.
4. **Automated Architecture Sync & File Scaffolding:** Use `python3 .agents/scripts/tiertask_dev.py scaffold <rel_path> --desc "<summary>"` when creating new `.dart` files and `python3 .agents/scripts/tiertask_dev.py arch --sync-tree --set <rel_path> "<summary>"` when updating `ARCHITECTURE.md`.

## 1. TDD Edit-Analyze-Test Cycle (`P-TDD-FIRST`)
1. **Verify Baseline:** Run `python3 .agents/scripts/tiertask_dev.py verify --fast` before editing files.
2. **Red Phase (Write Failing Tests First — `P-TDD-FIRST`, `P-TEST-MIRROR`):**
   - Before writing or modifying production code in `lib/`, write or update unit tests or widget tests in `test/` mirroring `lib/<layer>/<name>.dart` in `test/<layer>/<name>_test.dart` (or its mapped subsystem test suite in `tiertask_dev.py`) (`P-TEST-MIRROR`).
   - Use `pumpLeafWidget` (`FakeTaskNotifier`) in `test/ui/test_helpers.dart` when testing isolated leaf widgets without booting the full `TierTaskApp`, and call `HttpOverrides.global = null;` in `setUp()` for any repository test binding a loopback `HttpServer` (`P-TEST-MIRROR`).
   - Do not enforce line-count caps on test files or split existing test suites solely to reduce line count.
   - Run `flutter test --no-pub --no-test-assets -r failures-only <target_test_file>` and confirm that the new or updated test fails for the expected reason.
3. **Green Phase (Minimal Production Implementation — `AGENTS.md` Sections 1–3, `P-FILE-SIZE`, `P-CLASS-COHESION`, `P-ACYCLIC-DAG`):** Place core logic in dedicated `snake_case.dart` leaf files organized by domain or widget responsibility (forbidding `part`/`part of` and `export` shims, and never refactoring or compressing existing code solely to reduce line count):
   - **Layout, Class Cohesion & Imports (`P-LICENSE-HEADER`, `P-DIRECTIVES-ORDER`, `P-CLASS-COHESION`):** Follow the 7-part vertical layout (verbatim GPL-3.0 header + blank line + `///` docs + 3-group alphabetized imports: `dart:`, `package:`, relative imports in `lib/` or `package:tiertask/` in `test/`). Keep each class focused on a single cohesive responsibility (`P-CLASS-COHESION`), extracting stateless helper classes (`const Class._()`) into dedicated leaf files only when a distinct functional subsystem emerges. Order class members strictly (constructors, `static const`/`static final`, `final` fields, getters, lifecycle overrides, public methods, `_private` methods, `==`/`hashCode`/`toString`).
   - **Types, Immutability & Docs (`P-FN-DOCS`, `P-IMMUTABLE-MODELS`, `P-CONST-WIDGETS`, `P-NO-DEAD-CODE`, `P-LANG-RULES`):** Favor immutable models (`const` constructors, `final` fields, `List.unmodifiable`, `copyWith`, value `==` and `hashCode`), `enum` / `sealed class` states over boolean flags, and `super.key` on widgets. Document every production item (`public`, `_private`, and extracted helpers) with concise English `///` comments (ASD-STE100 80%, zero emojis); omit redundant `///` on `test()` blocks. Write only directly called items.
   - **Google Flutter Architecture, Acyclic DAG, Security & Resilience (`P-UDF-ARCHITECTURE`, `P-ACYCLIC-DAG`, `P-IO-ISOLATION`, `P-WEBDAV-API`, `P-GLOBAL-ERROR-BOUNDARY`, `P-ATOMIC-STATE`, `P-SECRET-HYGIENE`, `P-TRANSPORT-SECURITY`):** Enforce unidirectional data flow (`UI -> Notifiers -> Services/Repositories`) and **`0` circular import SCCs** across `lib/` with strict bottom-up layer ranking (`app_logger < models < l10n < services < repositories < providers < ui < main`, `P-ACYCLIC-DAG`). Isolate all `HttpClient`, `File`, and `FlutterSecureStorage` calls in `lib/repositories/` (zero `dart:io` imports in `lib/models/`, `lib/services/`, and `lib/ui/`), guard global errors (`FlutterError.onError`, `PlatformDispatcher.instance.onError`), preserve/roll back state on failed persistence, redact credentials from `toString()`/exceptions, never bypass TLS (`badCertificateCallback`), and avoid `runtimeType.toString()` checks that break `--obfuscate`.
4. **Refactor Phase — Flatness, Readability & Performance Gate (`P-VERTICAL-CLARITY`, `P-FILE-SIZE`, `P-CLASS-COHESION`, `P-FLAT-CONTROL-FLOW`, `P-FLATTEN-BUILD`, `P-NO-NESTED-LOOPS`, `P-LOOP-MODULARITY`, `P-FUNCTIONAL-COMBINATORS`, `P-ZERO-ALLOC`, `P-BOUND-ALLOC`, `P-LAZY-LISTS`, `P-DISPOSE-RESOURCES`):**
   - Enforce zero nested loops (`P-NO-NESTED-LOOPS`), indentation $\le 3$ levels (`P-FLAT-CONTROL-FLOW`), loop bodies $< 25$ lines (`P-LOOP-MODULARITY`), and `build()` / dispatcher methods $< 40$ lines (`P-FLATTEN-BUILD`). Never refactor, compress, or split existing files solely to reduce line count (`P-FILE-SIZE`).
   - Extract UI subtrees into dedicated `const` `StatelessWidget` or `ConsumerWidget` classes rather than helper methods returning `Widget`.
   - Deconstruct nullable values and sealed types via Dart 3 pattern matching (`switch`, `if (value case final v?)`), `??`, or `?.` (never check `!= null` then force-unwrap with `!`). Prefer flat `for` loops calling a helper over complex combinator chains (`P-FUNCTIONAL-COMBINATORS`, `P-VERTICAL-CLARITY`).
   - Eliminate avoidable loop/build allocations (compile `RegExp` as `static final`, use `StringBuffer` for serialization, use `ListView.builder` for dynamic task lists), check `max*` resource bounds before scanning or allocating the $(N+1)$-th element (`P-BOUND-ALLOC`), and dispose all controllers, streams, and `HttpClient` instances (`P-DISPOSE-RESOURCES`).
5. **Fast Iterative Verification & Parallel Subagent Isolation (`verify --fast --fix`, `P-SUBAGENT-ISOLATION`):** During development iterations, run `python3 .agents/scripts/tiertask_dev.py verify --fast --fix` to auto-format modified `.dart` files, verify static `AGENTS.md` invariants (`P-LICENSE-HEADER`, `P-FILE-SIZE`, `P-ACYCLIC-DAG`, `P-NO-IGNORE`, `P-IO-ISOLATION`, `P-LANG-RULES`), run `flutter analyze --no-pub --fatal-infos --fatal-warnings`, and execute the mapped mirror/subsystem test suites in `< 5s` via `--no-pub --no-test-assets -r failures-only`. When running parallel subagents, assign strictly disjoint file `Write Set`s (`P-SUBAGENT-ISOLATION`) and have each subagent run only its assigned test suites before running `verify --full --fix` at the wave barrier.
6. **Sync Spec, Docs & Changelog:** Follow **`tdf-spec-workflow`** whenever `spec/TDF_SPEC_0.6.0.md` or TDF parsing/evaluation rules change, **`update-documentation`** (`README.md`, `ARCHITECTURE.md`, `AGENTS.md`), and **`changelog-updater`** (`CHANGELOG.md`).
7. **Final Full Verification & Stamp (`verify --full --fix`):** Run `python3 .agents/scripts/tiertask_dev.py verify --full --fix` once at the end of the task to run the complete test suite and write the verified SHA-256 tree stamp (`.dart_tool/tiertask_verify_stamp.json`).

## 2. Testing Standards (`flutter test`, `P-TEST-MIRROR`)
- **Coverage, Harness & Assertions:** Write unit and widget tests in `test/<layer>/` (`models`, `services`, `repositories`, `providers`, `ui`) for every feature, parser routine, state transition, repository method, widget interaction, or bug fix. Use `pumpLeafWidget` (`FakeTaskNotifier`) for isolated leaf widgets, call `HttpOverrides.global = null;` in `setUp()` for loopback `HttpServer` repository tests (`P-TEST-MIRROR`), use semantic matchers (`contains()`, `equals()`, `isA<T>()`, `throwsA(isA<DomainException>())`) over brittle exact-string checks, and include concise `reason:` strings in `expect(..., reason: '...')` for loops, table-driven cases, and state transitions.
- **Required Edge Cases (`AGENTS.md` Section 5):** Cover all `enum` and `sealed class` branches (`M-EXHAUSTIVE-STATE-TESTS`), WIP/retention/`max*` boundaries (`M-EXTREME-BOUND-TESTS`), TDF delimiter/quote/escape/comment/newline/control injection (`M-DELIM-INJECT-TESTS`), generic WebDAV URI and local/remote path traversal edge cases (`M-URI-PATH-EDGE-TESTS`), and isolated HTTP, local file, and secure storage failure tests via mock repositories, temporary directories (`Directory.systemTemp`), or loopback `HttpServer` (`M-IO-TESTS`).
