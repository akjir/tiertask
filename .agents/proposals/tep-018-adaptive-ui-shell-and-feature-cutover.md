# TEP-018: Phase 3 Adaptive UI Shell, Model-Free Presentation Layer, and Feature Cutover

> [!NOTE]
> Superseded in architecture by [`TEP-020`](tep-020-unified-ui-integration-and-reactive-architecture.md): `TEP-020` dissolved the standalone `packages/tiertask_ui/` package split and retired the mandatory `lib/presentation/` adapter layer by integrating the 24 design-system modules into `lib/ui/{tokens,primitives,layout,components}/` and restoring direct reactive `lib/ui/ -> lib/providers/` state access while preserving 100% of the visual design system and UX contracts.

## Part 1: Concept & Proposal

### 1.1 Summary
This proposal specifies **Phase 3** of umbrella proposal [`TEP-015`](tep-015-ui-architecture-and-design-system-roadmap.md). It introduces a model-free presentation ViewModel and intent controller layer under `lib/presentation/`, migrates persisted theme palettes from legacy `Slate`/`Navy` to `Calm` (default) and `Plum Umber`, enforces the strict Rank `7` UI import whitelist on `lib/ui_v2/` in `.agents/scripts/tiertask_dev.py`, builds the complete adaptive desktop and mobile feature UI under `lib/ui_v2/` composed from `packages/tiertask_ui/` in compliance with [`spec/UI_DESIGN_SYSTEM.md`](../../spec/UI_DESIGN_SYSTEM.md), achieves full functional and `en`/`de` localization parity across Linux, Android, and Windows, and switches `lib/main.dart` unconditionally to the new shell upon parity completion. Legacy `lib/ui/` deletion and global strict locking remain scoped to Phase 4 (`TEP-019`).

### 1.2 Motivation
Phase 1 ([`TEP-016`](tep-016-presentation-layer-decoupling.md)) removed direct `lib/repositories/` and `lib/services/` imports from legacy `lib/ui/`, and Phase 2 ([`TEP-017`](tep-017-dedicated-ui-component-library.md)) delivered the compiler-isolated 17-widget `packages/tiertask_ui/` library and WCAG AA verified `Calm` and `Plum Umber` token presets. Three architectural gaps prevent running the redesigned UI in production:
1. **Model and Provider Coupling in Phase 1 Presentation APIs:** Existing Phase 1 controllers in `lib/presentation/` (`evaluatedBoardProvider`, `TaskEditorController`, `LabelEditorController`, `LocationEditorController`, `SettingsController`, `TaskInfoController`) still accept or expose `lib/models/*` types (`TaskBoard`, `TaskItem`, `WebDavConfig`, `TaskLink`, `TaskCondition`, `GeocodingCandidate`) so legacy `lib/ui/` compiles without a throwaway rewrite. Under `TEP-015`, new feature UI files in `lib/ui_v2/` MUST have zero imports from `lib/models/`, `lib/services/`, `lib/repositories/`, `lib/providers/`, or legacy `lib/ui/`.
2. **Missing Adaptive Feature Shell and Unified Entity Cards:** `packages/tiertask_ui/` is not yet wired into root `pubspec.yaml`, and no production feature adapters connect `lib/presentation/` to `UiAdaptiveAppShell`, unified expandable entity cards, uncommitted draft cards, docked Quick-Add/action footers, floating Undo notices, Settings dual-persistence, Conflict/Recovery views, or `UiDialogFrame` modals.
3. **Legacy Theme Enum and Build Chrome:** `WebDavConfig.themePalette` still persists legacy `AppThemePalette.slate` and `AppThemePalette.navy`, and `lib/main.dart` still mounts legacy `AppThemeSet`, `HomeScreen`, and a top-right `DEV` corner `Banner` ribbon instead of `UiThemePresets` and the inline chrome `DEV` pill (`U-BRAND-002`).

### 1.3 Goals & Non-Goals
- **Goals:**
  - Wire `packages/tiertask_ui/` into root `pubspec.yaml` and permit only strictly additive, non-breaking refinements to its existing 17 widgets when adapter wiring uncovers a missing optional slot, focus hook, callback, or semantics key (preserving the 17-widget cap, zero app/Riverpod dependencies, and package test coverage).
  - Add dedicated, model-free v2 ViewModels and intent controllers under `lib/presentation/` (sharing pure validation and formatting helpers with Phase 1 controllers) without breaking legacy Phase 1 controller APIs used by retained `lib/ui/`.
  - Centralize cross-view shell navigation, `returnContext`, tier/label filtering, global search, single-expand coordination, active inline section edit/draft state, unified desktop `Escape` / Android `PopScope` unwinding, and floating notice/Undo timers inside `lib/presentation/` `Notifier`s.
  - Migrate `AppThemePalette` to `calm` (default) and `plumUmber` with silent, zero-warning backward decoding of legacy `'slate'`, `'navy'`, and `TTW\x02` IDs `0`/`1` to `calm`, while keeping retained legacy `lib/ui/` compiling and green until Phase 4.
  - Enforce the full strict Rank `7` import whitelist and `P-IO-ISOLATION` on `lib/ui_v2/*` in `.agents/scripts/tiertask_dev.py` (forbidding `lib/models/`, `lib/services/`, `lib/repositories/`, `lib/providers/`, legacy `lib/ui/`, `packages/tiertask_ui/src/`, `dart:io`, and `dart:ffi`).
  - Deliver 100% TierTask `0.8.0` feature parity and complete `en`/`de` localization across Linux, Android, and Windows matching `.agents/prototypes/ui_v2/` and [`spec/UI_DESIGN_SYSTEM.md`](../../spec/UI_DESIGN_SYSTEM.md) (`U-FIDELITY-001`), while syncing `spec/UI_DESIGN_SYSTEM.md` to canonical TDF `0.8.0` bounds (`U-COMP-005` / `U-COMP-006` / `U-CARD-006`), exact manual UTC offset count (`U-UX-006`: `37` offsets), and platform-capability gating for Local `Move`/`Select` (`U-UX-006`).
  - Perform an unconditional cutover in `lib/main.dart` once all `lib/ui_v2/` views and verification gates pass, replacing the legacy top-right `DEV` corner `Banner` with the inline chrome `DEV` pill (`U-BRAND-002`) while keeping `TierTask (Dev)` window titles and migrating retained legacy `test/ui/` suites onto a test-only `LegacyTierTaskApp` harness in `test/ui/test_helpers.dart` so `verify --full --fix` passes cleanly until Phase 4.
- **Non-Goals:**
  - Any modification to [`spec/TDF_SPEC_0.8.0.md`](../../spec/TDF_SPEC_0.8.0.md) lexical grammar, directives, 6-tier derivation, resource bounds, or three-way sync rules.
  - Deleting legacy `lib/ui/` files, legacy `test/ui/` suites, Phase 1 legacy controller APIs, or retired legacy ARB keys (all deferred to Phase 4 under the bounded `TEP-015` cutover-window exception to `P-NO-DEAD-CODE`).
  - Adding new widgets beyond the 17-widget catalog in `packages/tiertask_ui/`.
  - Adding unsupported platforms (iOS, macOS, Web), non-WebDAV backends, or drag-and-drop manual queue reordering.

### 1.4 Description

#### Adaptive Shell, Chrome, Sidebar & Inline Filter (`U-LAYOUT-001`..`007`, `U-BRAND-001`..`004`)
- **Single-Frame Adaptive Shell (`UiAdaptiveAppShell`):** Top `62px` chrome bar, `244px` persistent desktop sidebar (`> 720px`) or `min(300px, 92%)` slide-over drawer (`<= 720px`), scrollable main pane paired with the non-blocking floating notice overlay (`maxWidth: 620px`), and a strictly decoupled conditional bottom dock (`bg` fill, top `1px` `line` border) for Task Quick-Add or Settings/Conflict/Recovery action footers.
- **Top Chrome Bar:** Desktop renders Brand (`UiAppLogo` + `TierTask` + inline `DEV` pill when `AppBuildProfile.isDev`), Workspace switcher pill, flexible spacer, Global Search toggle/input, conditional Location Status icon button (shown only when `locationEnabled`), and Sync status button (icon + label: `Local only`, `Synced`, `Syncing...`, `Conflict`, `Sync error`). Compact (`<= 720px`) reveals the `44x44px` menu toggle, moves Workspace into the top of the drawer, collapses Sync to icon-only, expands active Search to `100%` width, and replaces the brand slot with clickable `UiAppLogo` + active label name on compact Tasks view (`!searchOpen`).
- **Collapsible & Filterable Sidebar (`UiSidebarSection`):** Four sections (`Tasks` with live 6-tier counts; collapsible/filterable `Labels` leading with `All Tasks` and split primary filter + trailing `info` hub link; collapsible/filterable `Locations` with open counts; `Tools` with conditional `Sync with WebDAV`, conditional `Diagnostic Log`, `Raw TDF 0.8.0`, and `Settings`), plus a bottom-pinned SemVer build footer (`Version X.Y.Z` + dimmed `+<build>`).
- **Scroll Preservation:** Maintain independent `ScrollController` offsets for the sidebar (while workspace is unchanged), main list (while workspace, view, tier, label filter, and search state are unchanged), and label picker list, and smoothly reveal newly expanded or navigated entity cards (`Scrollable.ensureVisible`).

#### Tasks, Search, Unified Expandable Entity Cards & Draft Creation (`U-CARD-001`..`006`, `U-UX-002`..`004`)
- **Tasks & Global Search:** Tasks view shows `UiPageHeader` (with `N / 3` Focus and `N / 5` Ready tabular WIP limits, inline clickable desktop active-label filter, and subtitle) plus a compact native tier selector dropdown (`<TierName> · <count>`, zero horizontal swipe gestures). Global Search filters across all six tiers within the active workspace and active label filter (rendering inline active-label filter in the compact Search heading row and showing a `tone-soft` Tier badge on every result card).
- **Single-Expand Unified Entity Cards:** Tasks, Labels, and Locations share `UiCard` single-expand accordion behavior (`{ kind, id }`). Collapsed task cards show metadata in strict deterministic order: assigned label chips, primary badges (Tier in Search only; Due/Overdue with `danger`/`warning`/neutral tone), and up to `3` secondary badges (`Priority`/`due.auto` -> `Suspended` -> `BlockedBy` -> `Conditions` -> `Subtasks` -> `Repeat` -> `Note` -> `Links` -> `History`) plus a clickable `+<N> more` overflow chip.
- **Expanded Card Anatomy, Live Controls & Single Inline Editor:** Expanded headers display a hairline divider, monospace `ID: <id>`, Copy ID, contextual status pill (`Completed · restore task to edit` or `<N> open`), and inline Trash -> `Keep` / `Yes, delete` confirmation. Only populated sections render in canonical vertical order alongside a bottom `+ Add` chips bar for unset sections (plus solid `Priority`/`Someday` quick toggles for active queued tasks). At most one section editor is active at a time (`accent` border, re-elevated `panel` inputs, optional left danger clear button, right `Cancel` + `Save`). Live controls commit immediately without Save/Cancel: subtask checkboxes (triggering auto-finish, Undo push, card collapse, and Undo toast when the last step completes), History journal add/edit/delete, Task Placement switch, Task Label removal and Searchable Label Picker toggles, and Label Board Scope switch. Completed tasks stay read-only while preserving Restore, Copy ID/Note, external Links, entity navigation, Delete (with Undo), and interactive History.
- **Hybrid Date/Time Editing & Canonical TDF `0.8.0` Bounds:** Due, Suspended, and History timestamp override fields use editable `UiFieldKind.text` (`YYYY-MM-DD HH:MM`) paired with compact calendar and clock `trailingAction` buttons opening Material `showDatePicker` and `showTimePicker`; Condition time windows use editable `HH:MM` text fields paired with a clock picker trigger. All inputs enforce canonical `lib/models/tdf_error.dart` bounds measured in decoded Unicode scalar values (`TDF-TYPE-001` via `TdfCalendar.countUnicodeScalars`: `maxTdfHistoryPerTask = 500`, `maxTdfTextLength = 500`, `maxTdfNoteLength = 2000`, `maxTdfUriLength = 2048`, `maxTdfLinksPerTask = 20`, `maxTdfLinksPerLabel = 20`, `maxTdfArgsPerStmt = 64`, `maxTdfStmtsPerBlock = 1024`, `maxTdfConditionRulesPerEntity = 512`, `maxTdfLocationRefsPerEntity = 63`, `maxTdfBlocksPerDoc = 4096`, `maxTdfLocations = 200`, `maxTdfLocationRadius = 100000`, `maxTdfRepeatCount = 3650`, `maxTdfFileBytes = 1048576`, `maxTdfLineCount = 16384`), aligning prototype-inherited narrower UI caps (`U-COMP-005`, `U-COMP-006`, `U-CARD-006`) to canonical TDF `0.8.0` limits so existing valid `.tdf` documents never truncate on edit.
- **Non-Jumping Quick-Add, Quick-Create & Uncommitted Draft Cards:** Docked `UiQuickComposer` (collapsed to `+ New task` on compact viewports) creates tasks without switching tiers, scrolling, or auto-expanding, announcing placement via floating toast (`Moved to scoped queue: <label>`, `Saved · now in <Tier>`, or `Task saved`). Clicking `Open as draft` on Tasks, Labels, or Locations opens an accent-bordered uncommitted Draft Card at the top of the view, hiding the docked Task Quick-Add composer (or replacing the Label/Location quick-create bar in place) until created or cancelled. Label Quick-Create assigns the next rotating preset color; Location Quick-Create seeds the active GPS fix when available.
- **Context-Preserving `returnContext`:** Opening a Label or Location from Tasks or Search (via label chip, expanded chip, sidebar `info`, picker `info`, or condition location chip) stores `{ view, tier, label, searchOpen, searchQuery, expandedEntity }` and shows `Back to search` or `Back to tasks`, restoring exact context and scrolling back to the task. Direct chrome or sidebar navigation clears `returnContext`.

#### Settings, Capability-Gated Local Files, Diagnostics, Conflicts & Modals (`U-UX-005`..`007`)
- **Settings Dual-Persistence & Unsaved Draft Policy:** `Language`, `Appearance`, `Color Palette` (`Calm`, `Plum Umber`), `Time Zone` (automatic or `37` manual UTC offsets from `WebDavConfig.supportedUtcOffsetMinutes`), `Deadline Auto-Priority`, `Location`, `Diagnostic Logging` (enable, level, log storage mode, open viewer), `Storage Mode`, `Local File` actions, and `Local Watch` auto-save immediately (`Auto-saved` badge). Switching `Storage Mode` to `local` immediately clears any unsaved WebDAV dirty state and inline validation errors (`U-UX-006`). Editing WebDAV `serverUrl`, `username`, `password`, or `filePath` marks Settings dirty (`Unsaved changes` badge in both card header and docked footer), validates HTTP(S) scheme/host, userinfo rejection, credentials, and remote path traversal (`..`, `\`, control chars) inline and via top banner, and swaps primary emphasis between `Save` (when dirty) and `Test Connection / Sync Now` (when clean, disabled in `local`-only mode). Navigating away from Settings or switching workspaces discards unsaved WebDAV edits cleanly without modal prompts and re-hydrates from persisted config on return.
- **Capability-Gated Local Storage Actions:** Both `Move` (enabled vs disabled with desktop-only tooltip) and `Select` (native OS file chooser vs in-app `UiDialogFrame` + `UiSearchablePicker` `.tdf` modal) gate on OS capability (`supportsNativeDirectoryPickerProvider`) rather than viewport width, keeping narrow Linux/Windows windows functional and preventing unsupported native calls on wide Android tablets.
- **Secondary Views & Modals:** Full-height `Diagnostic Log` view (`Min Level`, `Subsystem` tag, severity-tinted monospace console, conditional `Upload Log`, `Copy All`, `Scroll to Bottom`, `Clear` preserving `@meta`), full-height `Raw TDF 0.8.0` view (byte/line telemetry, `Copy`, or `1 MiB`/`16,384`-line limit-exceeded warning), full `Deletion Conflict (TDF-DEL-003)` and `Recovery (TDF-REC-002)` views across tasks, labels, and locations with docked `Cancel` + `Apply & Sync` footer (backed by structured `TdfSyncOutcomeException` retention on `SyncState`), initial loading and full-screen file-read error states, and `UiDialogFrame` modals (`Workspaces`, `Location Status`, `Select/Rename Local File`, typed-filename `Wipe Local/Remote TDF`, `Geocoding Candidates`, and compact `Label Picker` bottom sheet without search auto-focus; custom HSV color selection uses `UiColorWheel`'s built-in `UiDialogFrame` modal directly).

#### Keyboard Shortcuts, Android `PopScope` & Live External Update Resilience (`U-A11Y-001`..`005`)
- **Desktop Keyboard & Unified Unwind Stack:** Desktop supports `Ctrl/Cmd+F`, `/`, `n`, `Ctrl/Cmd+Z`, `ArrowLeft`/`ArrowRight`, `Enter` form commits, and strict 9-layer `Escape` dismissal (`U-A11Y-002`). On Android, a root `PopScope` delegates to the same `AppShellController` unwind helper so system Back dismisses in-shell state in order (compact drawer -> label picker query -> sidebar label/location filter -> inline/popover label picker -> uncommitted entity draft -> global search -> active inline edit/delete confirm -> expanded entity card -> `returnContext` or secondary view to `tasks`) and permits OS exit only from a clean `tasks` root view (while active `UiDialogFrame` modals and compact bottom sheets pop first via `Navigator`).
- **Live External Board Updates & Mid-Flight Saves:** `TierTaskShellScreen` actively watches `boardBoundaryTimerProvider` so due, lead-window, suspension, and condition time boundaries continue ticking after cutover from `HomeScreen`. When external local file watch, boundary timer ticks, or WebDAV sync updates `TaskBoard` while a card is expanded or an inline section editor is open, keep the card expanded and preserve active inline edit text buffers while refreshing non-edited sections live. Auto-close the card and editor with a floating notice only when the entity was deleted externally or became completed externally while editing a non-History section (suppressing external notices for user-initiated local Delete/Complete/Subtask auto-finish mutations, and clearing `activeLabelId` if the filtered label was deleted externally). Guard async commits with an in-flight busy `Save` state, serializing mutations and keeping the inline editor open with an inline error on failure.

### 1.5 Alternatives
- **Refactoring Phase 1 Controllers In-Place (`lib/presentation/`):** Rejected because legacy `lib/ui/` screens and tests still depend on Phase 1 signatures (`TaskEditorDraftInput`, `evaluatedBoardProvider` returning `AsyncValue<TaskBoard>`, `WebDavConfig`); adding dedicated v2 ViewModels and intent controllers avoids touching ~24,000 lines of soon-to-be-deleted legacy UI code before Phase 4.
- **Keeping Transient Shell, Navigation, Expand, and Toast State Inside `lib/ui_v2/` `StatefulWidget`s:** Rejected because centralizing shell state in `lib/presentation/` `Notifier`s keeps `lib/ui_v2/` thin and allows fast unit testing of 9-layer `Escape`, Android `PopScope`, `returnContext`, non-jumping creation, and external-update preservation in `test/presentation/`.
- **Replacing `AppThemePalette` Enum With a Raw `String themePresetId`:** Rejected because keeping `enum AppThemePalette { calm, plumUmber }` preserves compile-time exhaustive Dart 3 `switch` guarantees (`P-EXHAUSTIVE-SWITCH`) across `SettingsCodec`, `LegacyTtwV2Converter`, presentation, and UI while matching `UiThemePresets` string IDs `1:1`.
- **Temporary `--dart-define` Dual-Shell Flag in `lib/main.dart`:** Rejected because an unconditional cutover at parity completion avoids dead toggle plumbing (`P-NO-DEAD-CODE`) while legacy `lib/ui/` stays intact and compiled for easy revert until Phase 4.
- **Pure Tap-to-Pick Date/Time (`UiFieldKind.dateTime` Only):** Rejected because desktop Linux and Windows users benefit from direct keyboard entry (`YYYY-MM-DD HH:MM`, `HH:MM`) alongside native Material date and time pickers.
- **Gating Local `Move` on Viewport Width (`compact <= 720px`) Instead of Platform Capability:** Rejected because resized narrow Linux/Windows windows still support native directory picking while wide Android tablets do not; capability gating via `supportsNativeDirectoryPickerProvider` matches real platform behavior.
- **Freezing `packages/tiertask_ui/` Completely During Phase 3:** Rejected because small, strictly additive optional callbacks or focus/semantics hooks on existing widgets prevent brittle adapter workarounds in `lib/ui_v2/` while maintaining the 17-widget cap and package isolation.

## Part 2: Technical Design & Code Changes

### 2.1 Architecture & Affected Modules

#### Strict Rank `7` UI Import Whitelist (`lib/ui_v2/*`)
During Phase 3, `.agents/scripts/tiertask_dev.py` assigns `lib/ui_v2/*` to **Rank `7`** alongside legacy `lib/ui/*`, while enforcing the full target strict UI whitelist exclusively on `lib/ui_v2/*`:
- **Allowed imports in `lib/ui_v2/*` (strict whitelist; every other `import` URI is rejected):**
  - `package:tiertask_ui/tiertask_ui.dart` (never `package:tiertask_ui/src/...`)
  - Relative imports resolving to Rank `6` (`lib/presentation/*`, e.g., `../presentation/...` or `../../presentation/...`)
  - Acyclic intra-layer relative imports resolving within `lib/ui_v2/*` (never resolving to legacy `lib/ui/*`)
  - Relative import resolving to `lib/l10n/app_localizations.dart` (never `app_localizations_en.dart`, `app_localizations_de.dart`, `tier_localization_extension.dart`, or `storage_file_read_localization_extension.dart`)
  - `package:flutter_riverpod/flutter_riverpod.dart`
  - Flutter and `material_ui` packages (`package:flutter/...`, `package:material_ui/...`)
  - Non-I/O Dart SDK libraries (`dart:async`, `dart:math`, `dart:ui`, `dart:collection`)
- **Explicitly forbidden in `lib/ui_v2/*`:** Any non-whitelisted import (including `package:tiertask/*`, `lib/models/*`, `lib/services/*`, `lib/repositories/*`, `lib/providers/*`, `lib/ui/*`, `lib/main.dart`, `packages/tiertask_ui/src/*`, `package:flutter_secure_storage/*`, `package:intl/*`, `dart:io`, `dart:ffi`, `dart:isolate`), plus any reference matching `_FORBIDDEN_UI_PROVIDER_RE` or `HttpClient`.
- **Lower-layer isolation (`Ranks 0..6`) & global `tiertask_ui/src/` guard:** Enforce in `run_static_checks` that Ranks `0..6` (`lib/models/*`, `lib/l10n/*`, `lib/services/*`, `lib/repositories/*`, `lib/providers/*`, `lib/presentation/*`) have zero `package:tiertask_ui/*` imports (`lib/presentation/*` retains zero `lib/ui/*`, `lib/ui_v2/*`, `dart:io`, or `dart:ffi` imports), and forbid `package:tiertask_ui/src/*` across all root `lib/` and `test/` files.

### 2.3 Implementation Details

#### 1. Model-Free ViewModel & Controller Contract (`lib/presentation/`)
- **Strict Type Isolation:** Every public type, parameter, return value, and provider exported from the new `lib/presentation/*_v2_*.dart` and `app_shell_controller.dart` / `floating_notice_controller.dart` files uses ONLY Dart primitives, `DateTime` (only when formatted or picked locally without model types), presentation enums, and `@immutable` ViewModel classes with `List.unmodifiable`, `copyWith`, `==`, and `hashCode` (`P-IMMUTABLE-MODELS`).

- **Validation & Formatting Reuse:** Delegate timestamp parsing, local UTC conversion, note/history sanitization, link URI validation, coordinate/Plus Code decoding, and radius parsing directly to shared static and instance helpers on existing Phase 1 presentation controllers (`TaskEditorController`, `TaskInfoController`, `LocationEditorController`, `LabelEditorController`) so zero business rules are duplicated.

#### 2. Unified `Escape` (9-Layer) & Android `PopScope` State Machine (`AppShellController`)
Define one deterministic unwind method on `AppShellController`:
```dart
/// Resolution outcome for a keyboard `Escape` or Android system Back request.
enum ShellDismissOutcome {
  /// Dismissed an active in-shell layer; keep the application open.
  handled,

  /// Clean `tasks` root state reached; permit OS back navigation / exit.
  allowSystemPop,
}
```
- **Desktop `Escape` (`U-A11Y-002`):**
  - **When a `Navigator` modal or compact bottom sheet route (`UiDialogFrame.showModal` / `showBottomSheet`) is active:** Focus is trapped inside `_UiFocusTrapOverlay` (Layer 3). Any `UiSearchablePicker` hosted inside the modal or bottom sheet (`Compact Label Picker Sheet`, `Select Local File` modal) intercepts `Escape` first on its focused search node (`_searchFocusNode.onKeyEvent`), clearing a non-empty search query (Layer 1) and on a second `Escape` invoking `onRequestClose` (which MUST call `Navigator.of(modalContext).maybePop()` so `Escape` is not swallowed). All other modals/sheets pop immediately via `_UiFocusTrapOverlay`.
  - **When no modal route is active:** `AppShellController.handleEscape(...)` unwinds in exact order (closing an open compact drawer on narrow desktop viewports first if open):
    1. Clear non-empty inline/popover label picker search query (also handled locally by focused `UiSearchablePicker`)
    2. Close and clear open sidebar label/location filter
    3. *(Active `Navigator` modal/bottom sheet handled above by `UiDialogFrame`)*
    4. Close open inline/popover label picker
    5. Cancel open uncommitted entity draft card
    6. Close Global Search and clear query
    7. Cancel active inline section edit
    8. Cancel active inline delete confirmation
    9. Collapse expanded entity card
- **Android System Back (`PopScope`):** When no modal `Navigator` route is active, `AppShellController.handleSystemBack()` unwinds in order: close compact drawer (clearing any open sidebar filter inside it) -> run in-shell layers 1, 2 (closing any open sidebar filter on persistent `> 720px` tablet layouts), 4, 5, 6, 7, 8, 9 -> restore `returnContext` (or return from secondary views `labels`/`locations`/`settings`/`logs`/`rawTdf`/`conflict`/`recovery` to `tasks`) -> return `ShellDismissOutcome.allowSystemPop` only when already at a clean `tasks` root view.

#### 3. External Board Updates, Boundary Timer & Mid-Flight Async Guarding
- **Live Boundary Timer Subscription:** `TierTaskShellScreen` watches `boardBoundaryTimerProvider` (`NotifierProvider.autoDispose`) so due, lead-window, suspension, and condition time boundaries continue triggering automatic board re-evaluation after `lib/main.dart` replaces `HomeScreen`.
- **Board Reconciliation Listener in `AppShellController`:** Subscribe to `taskNotifierProvider` board updates inside `AppShellController.build()`:
  - **Stale Active Filter Label Cleanup:** If `activeLabelId` is non-null and no longer exists in the refreshed board's `labels`, clear `activeLabelId` using the standard `U-LAYOUT-004` filter-clear side effects.
  - **Local Mutation Suppression Guard:** `TaskV2Controller` and `EntityV2Controller` wrap user-initiated inline Delete, Complete, and Subtask Auto-Finish mutations in an `AppShellController` local-mutation guard (marking the target `EntityRef` before `TaskNotifier` updates `state = AsyncData(...)` and clearing it in `finally`) so local actions collapse cleanly and preserve their Undo toast rather than triggering spurious external-change notices.
  - **External Entity Preservation vs Auto-Close:** For non-local board refreshes while an entity is expanded or being edited inline:
    - If the entity still exists on the refreshed board (and, for tasks, did not transition from open to completed while editing a non-History section), keep `expandedEntity` and `activeInlineEdit` untouched so the user's in-progress text buffer is never clobbered while non-edited sections refresh live from `tasksViewModelProvider` / `labelsManagerViewModelProvider` / `locationsManagerViewModelProvider`.
    - If the entity was deleted externally, collapse the card, clear `activeInlineEdit`, and emit a `FloatingNoticeViewModel` (`entityRemovedExternallyNotice`).
    - If an edited open task was completed externally while editing a non-History section, cancel `activeInlineEdit` (keeping the card expanded in read-only completed mode) and emit `taskCompletedExternallyNotice`.
- **Mid-Flight Async Save Serialization:** Every async mutation intent in `TaskV2Controller`, `EntityV2Controller`, `SettingsV2Controller`, `WorkspaceV2Controller`, and `SyncV2Controller` tracks a per-operation in-flight guard (`isBusy`), prevents duplicate concurrent submits, awaits persistence (`unawaited_futures`), checks provider/widget liveness across `await`, and returns a typed sealed outcome (`V2ActionSucceeded`, `V2ActionValidationFailed`, `V2ActionPersistFailed`) so inline editors keep their open text buffer and display the localized inline error on failure.
