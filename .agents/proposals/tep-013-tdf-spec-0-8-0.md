# TEP-013: TDF Specification 0.8.0 Standalone Baseline, Canonical Runtime, Synchronization Hardening, and Conformance Suite

> [!NOTE]
> **Scope Partition (`status: review`):** This proposal specifies the complete transition of TierTask from `TDF 0.7.0` (and legacy `0.2.0`–`0.6.0` migration chains) to the standalone **`TDF 0.8.0`** baseline defined in [`spec/TDF_SPEC_0.8.0.md`](../../spec/TDF_SPEC_0.8.0.md), including the unified [`spec/conformance/v0.8.0/`](../../spec/conformance/) fixture suite, byte-exact canonical serialization, local schedule anchors (`due ... anchor ...`) with `(Y_cur, M_cur)` monthly recurrence progression, DST-aware `TdfTimeZoneContext.systemLocal()` resolution, stage-fair `TdfCleanupMode` synchronization (`finalStage` vs. `deferred`), pure-Dart `dart:ffi` host-local cooperative file locking (`TDF-PUB-002`) and atomic publication (`TDF-PUB-003`), conditional WebDAV `If-Match` / `If-None-Match: *` publication, `TTS\x04` per-target synchronization state, full `TDF-DEL-003` / `TDF-REC-002` domain/provider resolution APIs, and `EditTaskScreen` / `TaskInfoDialog` local calendar alignment. Interactive Material 3 modal dialogs for `DeletionConflict` and `RecoveryRequired` user prompts are deferred to a separate future UI proposal.

## Part 1: Concept & Proposal

### 1.1 Summary
`TEP-013` establishes [`spec/TDF_SPEC_0.8.0.md`](../../spec/TDF_SPEC_0.8.0.md) as the sole normative TierTask Data Format (`TDF`) specification in the repository, removes all pre-`0.8.0` version conversion and historical parser/serializer baggage (`0.2.0`–`0.7.0`), and upgrades the TierTask Flutter application across Linux, Android, and Windows to full `tdf 0.8.0` conformance (`TDF-META-001` through `TDF-TRACE-001`). It introduces optional local schedule anchors on deadlines (`due <utc> [anchor <local>] [passive] ["<note>"]`) with drift-free `(Y_cur, M_cur)` monthly progression, enforces the byte-exact canonical serialization profile (verified against SHA-256 `sourceDigest` Vectors `1`–`4`), fixes automatic OS time-zone evaluation and scheduling to honor historical and future DST transitions (`TDF-CTX-001`, `TDF-CAL-001`), formalizes `TdfCleanupMode` (`finalStage` vs. `deferred`) across multi-stage synchronization and local contention retries, serializes local writes via a non-unlinked host-local cooperative runtime lock outside synchronized folders (`TDF-PUB-002`), adds `If-None-Match: *` initial-creation protection on WebDAV `PUT` (`TDF-PUB-003`), upgrades persisted workspace sync baselines to `TTS\x04` (`TDF-MERGE-001`, `TDF-REC-001`), completes `TDF-REC-002` new-identity recovery in the domain and provider layers, and aligns `EditTaskScreen` and `TaskInfoDialog` with `TDF-CAL-001` local calendar semantics.

### 1.2 Motivation
The `0.7.0` codebase accumulated six structural limitations and specification gaps that [`spec/TDF_SPEC_0.8.0.md`](../../spec/TDF_SPEC_0.8.0.md) resolves:

1. **Legacy Migration Complexity & Maintenance Overhead:** Supporting load-time upgrades (`0.5.0`–`0.6.0 -> 0.7.0`) and explicit imports (`0.2.0`–`0.4.0 -> 0.7.0`) required over 2,000 lines of historical scanner/parser/serializer/importer code (`tdf_importer.dart`, `tdf_historical_parser.dart`, `tdf_historical_serializer.dart`, `tdf_id_migration.dart`), legacy error variants (`ImportContextRequired`, `MigrationIdentifierCollision`), out-of-band deletion timestamp maps (`deletedLabelTimestamps`, `deletedLocationTimestamps`) in `WorkspaceSyncState`, and dual statement bounds (`512` vs. `1_024`). Treating `tdf 0.8.0` as a clean standalone baseline eliminates multi-schema branching and shrinks the attack and maintenance surface.
2. **Month-End (`29..31`) Clamping Drift, Interval-Edit Drift, and Spring DST Gap Clock Drift on `due`:** Storing only a single UTC `due` timestamp loses whether `2026-02-28` originated on the 28th or was clamped from January 31 (and loses a `02:30` local deadline shifted to `03:30` across a spring-forward gap). Adding `anchor <YYYY-MM-DD> [<HH:MM[:SS]>]` on `due` (`TDF-DIR-004`) while advancing monthly recurrences from `oldDue`'s current local year-month `(Y_cur, M_cur)` (`TDF-CAL-003`) makes sequential `k = 1` completions commute with `k = 2` jumps and `repeat` interval edits (`repeat 1 months -> repeat 2 months` on clamped Feb 28 -> Apr 30) without embedding IANA zone IDs in `.tdf` files.
3. **Non-Canonical Serialization Divergences (`TDF-SER-001`–`TDF-SER-005`):** In `0.7.0`, `TdfLabel` omitted explicit `modified 1970-01-01 00:00` when equal to epoch (losing explicit-vs-omitted `modified` state required by `TDF-SER-001` and `TDF-MERGE-003` Criterion 4), and inline `condition` on `label` blocks was excluded from $W_{\text{dir}}$ keyword padding. `0.8.0` requires byte-for-byte identical UTF-8 output and SHA-256 `sourceDigest` reproduction across all implementations.
4. **Fixed-Offset OS Time-Zone Bug & UTC Editor Inputs (`TDF-CTX-001`, `TDF-CAL-001`, `TDF-MUT-008`):** `TaskSyncPipeline.resolveWorkspaceTimeZone` passed `TdfTimeZoneContext.fixedOffset(utcNow.toLocal().timeZoneOffset)` in `AppTimeZoneMode.automatic`, applying `now`'s UTC offset to future recurrence dates across CET/CEST DST transitions in violation of `TDF-CTX-001`. In addition, `EditTaskScreen` formatted and parsed `due` and `suspended` inputs as raw UTC rather than local civil wall-clock values resolved via `TDF-CAL-001`.
5. **Multi-Stage Sync Revision Inflation & Pre-Cascade `scoped` Label Reconstruction (`TDF-MERGE-006`, `TDF-MERGE-009`, `TDF-PUB-003`):** Intermediate local synchronization stages (including Step 3 local contention retries in `StorageMode.both`) must defer `suspended <= now` and `blocked` cleanup (`cleanupMode = deferred`) so local `modified` revisions are never inflated to wall-clock `now` ahead of authoritative remote WebDAV reconciliation. Pre-cascade label set reconstruction $L_{\text{before}}(T)$ (`TDF-MERGE-006`) must also exclude cascade-driven label absences $D^{\text{label}}_X$ so concurrent `scoped` label deletions still evict global-view-restricted tasks from `queue` (`TDF-MERGE-011`).
6. **Intra-Host File Races & Unconditional Initial WebDAV Creation (`TDF-PUB-002`, `TDF-PUB-003`):** Replacing `<target>` via `rename` without a shared host-local cooperative lock outside the synced workspace allows concurrent local processes to lose updates, while opening Windows lock files with default `FILE_SHARE_DELETE` or missing share flags either allows lock unlinking or fails contenders with `ERROR_SHARING_VIOLATION`. Similarly, initial WebDAV creation lacked `If-None-Match: *` precondition protection.

### 1.3 Goals & Non-Goals
* **Goals:**
  * Make [`spec/TDF_SPEC_0.8.0.md`](../../spec/TDF_SPEC_0.8.0.md) the sole normative format specification; delete `spec/TDF_SPEC_0.7.0.md`, `spec/conformance/v0.6.0/`, `spec/conformance/v0.7.0/`, and all legacy importer/historical parser/serializer/ID-migration code and tests; add superseding `> [!NOTE]` callouts to completed `TEP-003`, `TEP-004`, and `TEP-006`.
  * Extract pure-Dart FIPS 180-4 SHA-256 hashing into `lib/services/sha256_service.dart` (`Sha256Service.hashBytes`, `Sha256Service.hashHex`) with zero legacy migration methods (`P-NO-DEAD-CODE`, `P-STDLIB-FIRST`).
  * Enforce the strict single-version `tdf 0.8.0` header contract (`TDF-COMPAT-001`, `TDF-ENT-001`), exact depth-`2` `condition { ... }` and `subtasks` error precedence (`InvalidBlockHeader` on attached `{` before `LimitExceeded` on nested `{`, `MissingDirectiveArgument` on zero-arg identifiers, `InvalidCondition` on `any <args...>`, and `UnknownDirective` on other identifiers outside `{day, time, location, any}`), unconditional `MAX_STMTS_PER_BLOCK = 1_024`, and byte-exact canonical serialization (`Vectors 1–4`).
  * Implement `due ... [anchor <YYYY-MM-DD> [<HH:MM[:SS]>]] [passive] ["<note>"]` (`TDF-DIR-004`), `(Y_cur, M_cur)` Mode 2 monthly recurrence progression with `D_a` clamping (`TDF-CAL-003`), `TDF-MUT-007` `restoreTask` clearing of `(dueAt, dueAnchor, isDuePassive, dueNote)`, `TDF-MUT-008` local-to-UTC deadline and deferral mutations, `dueAnchor` coupling in payload comparison and occurrence merges (`TDF-MODEL-006`, `TDF-MERGE-002`, `TDF-MERGE-010`), and `TaskBoardUndo` `dueAnchor` snapshot/restoration.
  * Implement `TdfTimeZoneContext.systemLocal()` with exact `TDF-CAL-001` autumn-fold (earliest matching UTC instant) and spring-gap (epoch-second binary search `toLocal(u) < target < toLocal(u + 1s)` supporting positive and negative DST, with `0001`/`9999` and Windows pre-`1601` Win32 bounds safety) resolution for `AppTimeZoneMode.automatic`, plus named IANA zone support (`UTC`, `Europe/Berlin`, `America/New_York`) in `TdfTimeZoneContext.named()` without importing `dart:io` in `lib/models/`.
  * Implement `TdfCleanupMode` (`finalStage`, `deferred`), symmetric `TDF-REC-001` generation-refresh classification across multi-stage sync (`incoming.deleted.generation > acknowledgedGeneration` and `local.deleted.generation > incoming.deleted.generation`), pre-cascade $L_{\text{before}}(T)$ reconstruction (`TDF-MERGE-006`), atomic per-target `TTS\x04` `WorkspaceSyncState` storing canonical `tdf 0.8.0\n` serializer snapshots with nullable `acknowledgedLocalGeneration` / `acknowledgedRemoteGeneration` (`TDF-MERGE-001`, `TDF-REC-001`) and zero out-of-band deletion timestamp maps, and complete `TDF-DEL-003` / `TDF-REC-002` domain and provider resolution APIs (including recover-as-new Base62 ID generation, cross-entity reference rewriting, discarded-task `blocked` stripping, and `_undoStack` invalidation).
  * Implement `TDF-PUB-002` / `TDF-PUB-003` host-local cooperative locking and atomic temp-file publication via pure Dart SDK `dart:ffi` in `lib/repositories/host_file_lock.dart` (using non-blocking `LOCK_NB` / `LOCKFILE_FAIL_IMMEDIATELY` acquisition with bounded async backoff timeout, direct resolution of existing target symlinks, and bounded Windows `MoveFileExW` `ERROR_SHARING_VIOLATION` retries) and add tri-state `_cachedExists` `If-None-Match: *` initial-creation protection on WebDAV `PUT` in `WebDavRepository`.
  * Align `EditTaskScreen` `due`, `suspended`, and `history` inputs (`task_editor_history_section.dart`) to local wall-clock time via `TDF-CAL-001` (synchronously updating both controller text and initial comparison snapshots in `ref.listenManual` so unedited `dueAnchor` and autumn-fold `due`/`suspended`/`history` UTC instants are preserved verbatim), render a read-only schedule-anchor detail line in `TaskInfoDialog` on open tasks when `dueAnchor` differs from `TdfLocalDateTime.fromWallClock(localDue)`, and update `en`/`de` localization strings for `0.8.0` version errors, sync conflict/recovery status banners, and schedule-anchor info display.
  * Build the complete `spec/conformance/v0.8.0/` fixture suite (`parse_valid/`, `parse_invalid/`, `bounds/`, `merge/`, `timezone/`) and verification test suites covering all `93` active `TDF-*` Rule IDs.
* **Non-Goals:**
  * Runtime load-time conversion, explicit import, or external CLI conversion scripts for `< 0.8.0` `.tdf` files.
  * Interactive Material 3 modal dialogs for resolving `DeletionConflict` or `RecoveryRequired` in `lib/ui/` (deferred to a future UI TEP).
  * Adding an explicit `due.anchor` text input in `EditTaskScreen` or a searchable IANA time-zone picker in `SettingsScreen` (`AppWorkspace` `TTW\x02` schema remains unchanged).

### 1.4 Description
1. **Single-Version Loading & Localized Rejection (`TDF-COMPAT-001`, `TDF-ENT-001`):**
   * `TdfService.parse` / `TdfService.parseBytes` accepts only `tdf 0.8.0` as the first depth-`0` statement. Empty/comment-only inputs, non-`tdf` first statements, or bare `tdf` fail with `TdfErrorKind.missingVersionHeader`; any other version token (including `0.7.0`, `"0.8.0"`, or extra tokens) fails with `TdfErrorKind.unsupportedVersion` without modifying storage.
   * When synchronization encounters `TdfErrorKind.unsupportedVersion`, `TaskSyncPipeline` preserves the active board and baseline untouched and surfaces localized `en`/`de` messages (`errorUnsupportedTdfVersionLocal`, `errorUnsupportedTdfVersionRemote`, `errorUnsupportedTdfVersionBoth`) stating that TDF version `0.8.0` is required.
2. **Schedule Anchors & Local Calendar Editing (`TDF-DIR-004`, `TDF-CAL-001`, `TDF-CAL-003`, `TDF-MUT-008`):**
   * `TaskItem` stores `final TdfLocalDateTime? dueAnchor` (six proleptic Gregorian local calendar components `0001-01-01 00:00:00..9999-12-31 23:59:59`, invariant: `dueAt == null => dueAnchor == null`).
   * **Mandatory Local-Time UI Round-Trip Invariant:** Every user-facing date and clock in the application (`TierTaskPill` deadline badge, `TaskInfoDialog` `due`/`suspended`/`history` timestamps, and `EditTaskScreen` `due`/`suspended`/`history` inputs and pickers) MUST display and accept civil wall-clock time in the active workspace time zone, while `.tdf` persists UTC (`due`, `suspended`, `history`, `created`, `finished`, `modified`). Specifically, saving `12:00` in the app writes `11:00:00` UTC in winter (`CET`, `UTC+1`) or `10:00:00` UTC in summer (`CEST`, `UTC+2`) to `.tdf`, and reloading that `.tdf` displays `12:00` again across `TierTaskPill`, `TaskInfoDialog`, and `EditTaskScreen`.
   * In `EditTaskScreen`, `due` and finite `suspended` text inputs initialize from `configuration.toLocalWallClock(...)` (`YYYY-MM-DD HH:MM` when `second == 0`, `YYYY-MM-DD HH:MM:SS` when `second != 0`), tracking mutable initial comparison snapshots (`_initialDueText`, `_initialSuspendedText`, and `_editingHistoryInitialTimestampText` alongside `_initialDueAt`, `_initialDueAnchor`, `_initialSuspendedAt`, and `_editingHistoryOriginalEntry`). If `webDavConfigProvider` resolves asynchronously after `initState`, `ref.listenManual(webDavConfigProvider, ...)` updates **both** the `_initial*Text` comparison snapshot **and** the `TextEditingController` text synchronously (before listener side effects) for any field still equal to its prior `_initial*Text`. Saving an unedited `due` string (`trimmed == _initialDueText`) preserves `existingTask.dueAt` (including autumn-fold second occurrences) and `existingTask.dueAnchor` verbatim (and preserves `isDuePassive` unless toggled or explicitly promoted to `Priority`); saving an unedited `suspended` string (`trimmed == _initialSuspendedText`) preserves `existingTask.suspendedAt` verbatim; and unedited `history` entries (as well as entries whose `<text>` is edited in `EditTaskScreen` or `TaskInfoDialog` while their displayed timestamp matches `_editingHistoryInitialTimestampText`) preserve their stored `timestampUtc` verbatim without wall-clock re-parsing (`TDF-CTX-002`). Saving a newly entered or edited `due` local timestamp `(Y_in, M_in, D_in, h_in, m_in, s_in)` resolves `dueAt` to UTC via `TDF-CAL-001`, sets `dueAnchor = TdfLocalDateTime(Y_in, M_in, D_in, h_in, m_in, s_in)`, and resets `isDuePassive` according to the editor's auto-prioritize toggle (`false` when promoted to `Priority`). Saving a newly entered or edited finite `suspended` or `history` local timestamp resolves it to UTC via `TDF-CAL-001`. Clearing `due` clears `dueAt`, `dueAnchor`, `isDuePassive`, and `dueNote`.
   * In `TaskInfoDialog`, on open tasks (`!task.isCompleted && task.completedAt == null`) when `task.dueAt != null` and `task.dueAnchor != null` and `dueAnchor != TdfLocalDateTime.fromWallClock(localDue)` (comparing all six `(year, month, day, hour, minute, second)` components), `_buildDueStatusDetails` appends a read-only localized detail line (`taskInfoDueAnchorDetail` in `en`/`de`) displaying `dueAnchor.formatCompact()` (`YYYY-MM-DD HH:MM` when `second == 0`, `YYYY-MM-DD HH:MM:SS` when `second != 0`).
3. **Host-Local Cooperative Lock & Multi-Stage Sync (`TDF-PUB-002`, `TDF-PUB-003`, `TDF-MERGE-009`):**
   * Every local `.tdf` publication acquires an in-process async mutex keyed by `targetPathHash` (resolving existing `<target>` symlinks directly via `File(target).resolveSymbolicLinksSync()`, or resolving `<target>`'s parent directory + `<target_basename>` when `<target>` does not yet exist) followed by a non-blocking OS-level exclusive lock with bounded async backoff timeout (`lockAcquireTimeout = 5s`) on `<host_lock_dir>/tdf-<targetPathHash>.lock` (`$XDG_RUNTIME_DIR/tdf-locks` or `<os_temp_dir>/tdf-locks-<uid>` with `0700` dir and `0600` file permissions + `flock(LOCK_EX | LOCK_NB)` on Linux/Android; `%LOCALAPPDATA%\Temp\tdf-locks` + `CreateFileW(OPEN_ALWAYS, GENERIC_READ | GENERIC_WRITE, FILE_SHARE_READ | FILE_SHARE_WRITE)` omitting `FILE_SHARE_DELETE` + `LockFileEx(LOCKFILE_EXCLUSIVE_LOCK | LOCKFILE_FAIL_IMMEDIATELY, 0..1)` on Windows), never blocking indefinitely on a hung external lock holder, never creating `.tdf.lock` in the workspace folder, and never unlinking the host lock file on release.
   * Local atomic publication writes `.<target_basename>.tmp.<32_hex_csprng>` with exclusive creation (`O_CREAT | O_EXCL | O_WRONLY | O_NOFOLLOW` mode `0600` on POSIX/Android; `CREATE_NEW` on Windows), flushes file bytes (`fsync` / `FlushFileBuffers`) and POSIX parent directory, and atomically replaces `<target>` (`rename` on POSIX/Android; `MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` on Windows with bounded short retries on transient `ERROR_SHARING_VIOLATION` from sync clients or antivirus scanners).
   * In `StorageMode.local`, the guarded local retry loop runs with `TdfCleanupMode.finalStage`. In `StorageMode.both`, Stage 1 (pre-WebDAV local reconciliation and its Step 3 contention retries) runs with `TdfCleanupMode.deferred`, Stage 2 (WebDAV reconciliation and `HTTP 412` retries) runs with `TdfCleanupMode.finalStage`, and Stage 3 (post-WebDAV local convergence and its Step 3 retries) runs with `TdfCleanupMode.finalStage`, keeping separate local and remote baselines in `WorkspaceSyncState` (`TTS\x04`).

### 1.5 Alternatives
* **Retain `0.7.0 -> 0.8.0` Load-Time Conversion:** Rejected per user decision (`DECISION-02`, `DECISION-08`); `spec/TDF_SPEC_0.8.0.md` is intentionally a clean standalone baseline with zero pre-`0.8.0` baggage.
* **Implement Host File Locks via Native C++/Kotlin `MethodChannel`s:** Rejected (`DECISION-03`) in favor of Dart SDK `dart:ffi` isolated in `lib/repositories/host_file_lock.dart`, which requires zero platform-runner channel boilerplate and allows real multi-process OS kernel lock contention tests directly under `flutter test`.
* **Keep `TTS\x01`–`TTS\x03` Sync State Decoding and Out-of-Band Tombstone Maps:** Rejected (`DECISION-06`); `TDF-MERGE-001` mandates invalidating baselines not bound to `0.8.0`, and `deleted` blocks inside `.tdf` make out-of-band label/location timestamp maps redundant and hazardous across generation advances.

### 2.2 TDF Schema, Localization & State Changes
1. **Domain Types & `TDF 0.8.0` Primitives (`lib/models/`):**

Remove `maxTdfLegacy060StmtsPerBlock` and `TdfException.targetVersion` in Wave 2 together with their last `lib/services/` callers; keep `TdfException.sourceVersion` solely for reporting offending `<version>` tokens on `TdfErrorKind.unsupportedVersion`.
   * `tdf_metadata.dart` & `tdf_location.dart`: Define `const String tdfSupportedVersion = '0.8.0'` (removing `TdfSchemaVersion` `v020..v070` in Wave 2 alongside `tdf_importer.dart` and `tdf_historical_*.dart`). Fix `TdfLabel.canonicalDirectChildStatementCount` and `TdfLocation` statement counting so an explicit `modifiedAt != null` is always counted and emitted even when `modifiedAt == 1970-01-01 00:00:00Z` (`TDF-SER-001`, `TDF-SER-003`).
   * `tdf_timezone.dart`:
     * Introduce `@immutable class TdfLocalDateTime` (`year`, `month`, `day`, `hour`, `minute`, `second`, `factory TdfLocalDateTime.fromWallClock(DateTime wallClock)`, validated against `TdfCalendar` proleptic Gregorian `0001-01-01 00:00:00..9999-12-31 23:59:59`, `formatExplicitSeconds()` -> `YYYY-MM-DD HH:MM:SS` called by `TdfSerializer`, `formatCompact()` -> `YYYY-MM-DD HH:MM[:SS]` called by `TaskInfoDialog`, value `==`/`hashCode`, and lexicographic `compareTo`).
