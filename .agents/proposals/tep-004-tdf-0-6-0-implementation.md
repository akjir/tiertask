# TEP-004: TDF 0.6.0 Runtime, Synchronization, and UI Conformance Implementation

## Part 1: Concept & Proposal

### 1.1 Summary
This proposal specifies the multi-stage implementation of the TierTask Data Format (`TDF`) version `0.6.0` ([`spec/TDF_SPEC_0.6.0.md`](../../spec/TDF_SPEC_0.6.0.md)) across the TierTask Flutter application (`lib/models/`, `lib/l10n/`, `lib/services/`, `lib/repositories/`, `lib/providers/`, `lib/ui/`, and `test/`). It builds upon the normative `0.6.0` specification and 54-file conformance test suite delivered in [`TEP-003`](tep-003-tdf-spec-0-6-0.md) and includes a dedicated `Locations` section in the navigation drawer (`HomeDrawer`) below `Labels` with an overview and detail editor (`EditLocationsScreen` and `EditLocationScreen`) analogous to label management.

### 1.2 Motivation
The TierTask codebase currently implements TDF `0.5.1` (`TdfBlockParser.supportedVersion = '0.5.1'`). While `TEP-003` finalized [`spec/TDF_SPEC_0.6.0.md`](../../spec/TDF_SPEC_0.6.0.md) and its executable conformance fixtures under `spec/conformance/v0.6.0/`, the runtime models, scanner/parser/serializer, `0.5.1 -> 0.6.0` migration pipeline, 6-tier evaluation rules, three-way merge engine, local file CAS-merge publication loop, and user interface do not yet implement the `0.6.0` specification.

### 1.3 Goals & Non-Goals
* **Goals:**
  1. Implement all `0.6.0` domain entities (`TdfLocation`, `TaskOrigin`), directives (`due`, `origin`, `label ... scoped`, `location` blocks, ID-referenced `condition location <loc-1> [<loc-2> ...]`, `deleted` `location` tombstones), resource bounds (`MAX_LOCATIONS = 200`, `MAX_LOCATION_RADIUS = 100000`, `MAX_LOCATION_REFS_PER_ENTITY = 63` counted before deduplication, `MAX_NUMBER_LENGTH = 24`), and error kinds (`UnknownLocationReference`).
  2. Implement the single-pass $O(N)$ `0.6.0` parser, canonical 6-section serializer (with explicit seconds `YYYY-MM-DD HH:MM:SS` for `deleted`, `queue.modified`, `suspended`, and `due`, and `YYYY-MM-DD HH:MM[:SS]` for `created`, `finished`, `task.modified`, `label.modified`, and `location.modified`), read-only in-memory `0.5.0 -> 0.5.1 -> 0.6.0` load-time conversion (without storage writes during loading per Sections 4.0 and 10.7), and explicit `0.2.0 -> 0.3.0 -> 0.4.0 -> 0.5.0 -> 0.5.1 -> 0.6.0` version import (`TDF-ID-MIGRATION-1` with `namespace = "location"` and `half-away-from-zero` rounding), passing all fixtures in `spec/conformance/v0.6.0/parse_valid/`, `parse_invalid/`, `bounds/`, `migration/`, and `timezone/`.
  3. Implement `0.6.0` 6-tier evaluation and ordinary mutation rules: global-view `scoped` label filtering ($L_{\text{global}}(T)$), active-filter-relative `Focus -> Ready` downgrade anchoring ($E_{\text{ctx}}$), standard completion preserving `due` and `origin`, Mode 2 schedule-anchored `repeat` + `due` + `suspended` local-calendar advancement with month-end lead-window preservation, task restoration (`restoreTask`, Section 6.5) removing `finished`, `suspended`, and `due` while preserving `origin`, `scoped` label deletion queue eviction, `label`-before-`task` location deletion cascade with `location any` inheritance-trap protection, and 30-day task tombstone expiry `blocked` cleanup.
  4. Implement `0.6.0` three-way merge unbundling (same-occurrence `priority`, `suspended`, `due`, `repeat`, per-`targetId` `blocked` map merge, step-wise `subtasks` boolean merge), pre-merge tombstone stripping and commutative `W`-anchored `locationGroup` merge, coupled `(coordinates, source)` location merge, newly introduced reference `DeletionConflict` detection ($A_X(T)$, $A^{\text{loc}}_X(E)$), explicit `Delete` and `Undelete` conflict resolution and `RecoveryRequired` (with new Base62 ID generation and `labels`, `blocked`, and `condition location` reference rewriting) across `task`, `label`, and `location` entities, and `Undelete` surviving-queue restoration, passing all 7 vectors in `spec/conformance/v0.6.0/merge/vectors.json`.
  5. Implement guarded local file publication across all local write paths (ordinary mutations, post-WebDAV remote-stage convergence, 30-day cleanup, and conflict/recovery resolution) with SHA-256 `localSourceDigest` tracking (`TTS\x03`), a bounded CAS-merge retry loop (`MAX_CAS_RETRIES = 3`) handling external edits, external creation (`loopB == null`), and external deletion (`RecoveryRequired`), and CSPRNG dot-prefixed `.tmp.<32hex>` atomic replacement without `.tdf.lock` files.
  6. Expose `0.6.0` features in the UI across Linux, Android, and Windows with English (`en`) and German (`de`) localization, including a `Locations` section in `HomeDrawer` directly below `Labels` and a dedicated `EditLocationsScreen` + `EditLocationScreen` workflow analogous to `EditLabelsScreen` + `EditLabelScreen`.
* **Non-Goals:**
  1. Adding network geocoding or third-party map tiles (`P-STDLIB-FIRST`, `P-IO-ISOLATION`).
  2. Modifying the normative rules already ratified in [`spec/TDF_SPEC_0.6.0.md`](../../spec/TDF_SPEC_0.6.0.md).

### 1.4 Description
* **Sidepanel (`HomeDrawer`) & Location Management (`EditLocationsScreen` / `EditLocationScreen`):**
  * Directly below the `Labels` section in [`lib/ui/widgets/home_drawer.dart`](../../lib/ui/widgets/home_drawer.dart), a new `Locations` section (`_DrawerLocationsSection`) renders a header with `Locations` and an `Edit` action button (`drawer_edit_locations_button`), followed by sorted location rows (`_DrawerLocationTile`, `drawer_location_tile_<id>`) with a location icon (`Icons.location_on_outlined`), `location.name`, and an open-task count badge (`drawer_location_badge_<id>`), plus a `+ Create new location` action tile (`drawer_create_location_tile`).
  * `TaskBoard.openTaskCountForLocation(String locationId)` counts open tasks (`!task.isCompleted`) for which `locationId` is active in the task's effective `location` condition group under Section 4.4.3: either directly via a task-level `LocationTaskCondition` containing `locationId`, or inherited from at least one assigned label's `LocationTaskCondition` containing `locationId` when the task does not specify `condition any`, `condition location any`, or a task-level `LocationTaskCondition` override.
  * Tapping `Edit` or `+ Create new location` in the drawer opens `EditLocationsScreen` (`lib/ui/edit_locations_screen.dart`), which mirrors `EditLabelsScreen`: a top create row (`_CreateLocationRow`) and an alphabetical `ListView.builder` of `_EditableLocationRow` cards with a delete button (`delete_location_button_<id>`), location icon, name and coordinate/radius summary, open task count badge (`edit_location_badge_<id>`), and edit button (`edit_location_button_<id>`).
  * Tapping a location tile in the drawer, tapping the edit button on a row in `EditLocationsScreen`, or submitting a new location name in `_CreateLocationRow` opens `EditLocationScreen`, a dedicated editor pane analogous to `EditLabelScreen` for editing `name`, `note`, `source`, `coordinates` (`latitude`, `longitude`), and `radius` (in meters). Duplicate location names across distinct `<location-id>` blocks are permitted per Section 4.3. When populating `coordinates` from the current device GPS fix via the GPS fill button, `EditLocationScreen` rounds raw `latitude` and `longitude` to at most 6 fractional decimal digits (`half-away-from-zero`) and formats them canonically so native `0.6.0` serialization never triggers `InvalidNumber`.
* **Task & Label Condition Editor (`TaskEditorConditionsSection`):**
  * In `TaskEditorConditionsSection`, the `location` condition subgroup replaces raw inline coordinate inputs with selectable `TaskEditorChip`s for each reusable `TdfLocation` defined on the board (`task_editor_condition_location_<id>`), alongside `location any` (when `allowResets` is true) and a button to open `EditLocationsScreen` / `EditLocationScreen` to create or manage locations.
* **Task `due` Timestamp & Label `scoped` Toggle:**
  * `TaskEditorSchedulingCard` and `EditTaskScreen` add a `due` date/time selector (`YYYY-MM-DD HH:MM:SS` in UTC, edited in local time) alongside `suspended` and `repeat`, while preserving any `origin` metadata on the task. `TierTaskPill` renders a concise `due` badge when `task.dueAt != null`.
  * `EditLabelScreen` adds a `scoped` switch card (`label <id> scoped {`) controlling whether tasks carrying only `scoped` labels are hidden from the global (`All Tasks`) view.

### 1.5 Alternatives
* **Inline-only location management inside `TaskEditorConditionsSection`:** Rejected based on user direction. Managing reusable `TdfLocation` entities in the navigation drawer below `Labels` with a dedicated `EditLocationsScreen` and `EditLocationScreen` provides consistent UX parity with `Labels` and reflects that `location` blocks are first-class root entities in TDF `0.6.0`.
* **Single monolithic implementation step:** Rejected because updating models, parser, evaluator, 3-way merge, repository CAS loop, and UI simultaneously would violate incremental TDD verification (`P-TDD-FIRST`) and parallel subagent isolation (`P-SUBAGENT-ISOLATION`).

### 2.3 Implementation Details & Stage Decomposition
Implementation is divided into 6 sequential bottom-up stages with disjoint file write sets (`P-SUBAGENT-ISOLATION`):
1. **Stage 1 — Foundation (`lib/models/`):** `tdf_error.dart`, `tdf_location.dart`, `tdf_metadata.dart`, `task_item.dart`, `tdf_sync_metadata.dart`.
2. **Stage 2 — TDF Scanner, Parser, Serializer & Migration (`lib/services/`):** `tdf_id_migration.dart`, `tdf_directive_parser.dart` (enforcing `MAX_LOCATION_REFS_PER_ENTITY = 63` on pre-deduplication `<location-id>` tokens), `tdf_parser.dart`, `tdf_serializer.dart` (enforcing Section 7.1 timestamp second-precision rules for `due` / `deleted` vs. `location.modified`), `tdf_historical_parser.dart`, `tdf_historical_serializer.dart`, `tdf_importer.dart` (`schemaRef051` and `migrate051To060`), `tdf_service.dart`.
3. **Stage 3 — 6-Tier Evaluator, `scoped` Filtering, Downgrade Anchor, `restoreTask` & Cascades (`lib/models/task_board*.dart`):** `task_board.dart` (`openTaskCountForLocation` with Section 4.4.3 inheritance), `task_board_evaluator.dart`, `task_board_queue_mutator.dart`, `task_board_mutator.dart` (including `restoreTask` clearing `dueAt` while preserving `origin`).
4. **Stage 4 — Three-Way Merge Unbundling, Condition Group Merge, `DeletionConflict` & Location Recovery (`lib/models/*sync*.dart`):** `tdf_payload_comparison.dart`, `task_board_reconciler.dart`, `task_board_sync.dart` (including `Delete` / `Undelete` conflict decisions and `RecoveryRequired` new-ID rewriting for `location` blocks and `condition location` references under Sections 6.8.2 & 6.8.4).
5. **Stage 5 — Guarded Local Publication (`sourceDigest`), Bounded CAS-Merge Loop Across All Local Write Paths & Temp-File Swap (`lib/models/workspace_sync_state.dart`, `lib/repositories/`, `lib/providers/sync_providers.dart`):** `workspace_sync_state.dart`, `local_file_operations.dart`, `local_file_repository.dart`, `sync_providers.dart` (applying the 3-retry CAS-merge loop to all local writes and handling external deletion/creation in Step 3).
6. **Stage 6 — Riverpod Notifiers, Sidepanel `Locations` & `EditLocationsScreen` (with 6-decimal GPS rounding), `due`/`scoped` UI & Docs (`lib/l10n/`, `lib/providers/`, `lib/ui/`, Docs):** ARB files, `task_providers.dart`, `home_drawer.dart`, `home_screen.dart`, `edit_locations_screen.dart`, `edit_labels_screen.dart`, `condition_editor_controller.dart`, `task_editor_conditions_section.dart`, `task_editor_scheduling_card.dart`, `edit_task_screen.dart`, `tier_task_pill.dart`, `.agents/scripts/tiertask_dev.py` (`_SUBSYSTEM_TEST_MAP`), and documentation sync.

### 2.4 Testing Strategy
Every stage follows strict Red-Green-Refactor TDD (`P-TDD-FIRST`, `P-TEST-MIRROR`):
* **`M-EXHAUSTIVE-STATE-TESTS`:** Cover `TdfErrorKind.unknownLocationReference`, all `0.6.0` parse/validation error branches across the 23 negative fixtures in `spec/conformance/v0.6.0/parse_invalid/manifest.json`, all 7 merge vectors in `spec/conformance/v0.6.0/merge/vectors.json`, `restoreTask` clearing `due` while preserving `origin` (Section 6.5), and `Delete` / `Undelete` / `RecoveryRequired` (with new Base62 ID rewriting) for `location` entities (Sections 6.8.2 & 6.8.4).
* **`M-EXTREME-BOUND-TESTS`:** Cover all 13 boundary fixtures in `spec/conformance/v0.6.0/bounds/manifest.json` (`MAX_LOCATIONS = 200` vs `201`, `MAX_LOCATION_RADIUS = 100000` vs `100000.01`, `MAX_NUMBER_LENGTH = 24` vs `25`, `MAX_LOCATION_REFS_PER_ENTITY = 63` vs `64` counted before deduplication, `origin` `500` vs `501` scalars), active-filter downgrade boundaries ($|E_{\text{ctx}}| = 0, 6, 7$), and 30-day task tombstone expiry `blocked` cleanup (`29`, `30`, `31` days).
* **`M-DELIM-INJECT-TESTS`:** Cover quoted `scoped` header rejection, `origin {` block rejection, single-line `<text>` decoded `\n`/`\r`/`\t` rejection, non-ASCII whitespace (`U+00A0`) retention, and canonical timestamp formatting (`YYYY-MM-DD HH:MM:SS` for `due` and `deleted.location` vs. `YYYY-MM-DD HH:MM[:SS]` for `location.modified`).
* **`M-URI-PATH-EDGE-TESTS`:** Cover `javascript:`, `vbscript:`, `data:`, and control-character URI rejection (`InvalidUri`) and `EmptyText`-before-`LimitExceeded`-before-`InvalidUri` precedence.
* **`M-IO-TESTS`:** Cover `.tmp.<32hex>` atomic local file replacement, unconditional temp-file cleanup on error, symlink rejection, zero `.tdf.lock` files, and the 3-retry CAS-merge loop across all local write paths (including external edit, external creation, and external deletion) in `test/repositories/local_file_repository_test.dart` and `test/providers/sync_providers_test.dart`.
